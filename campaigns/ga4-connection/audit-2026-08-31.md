# GA4 audit — code side

_2026-08-31. Verified against `src/` and against production HTML served from
thevalleycleanteam.com. The GA4-side half (what the property actually recorded)
runs once read access is granted — see `brief.md`._

## What is already correct

GA4 was never missing. Measurement ID `G-LXHE2DSZ7T` loads from
`src/layouts/BaseLayout.astro:226`, and it ships in production HTML (confirmed
on `/request-a-quote`, 200, tag present).

Three things in that file are done well and should not be "fixed":

- **Production-only guard** (`analyticsEnabled()`, line ~189). Preview
  deployments and localhost share this config, so without the hostname check
  every Lighthouse CI run on a `*.vercel.app` preview lands in the property as
  a new user. That was ~55% of events before PR #167.
- **gtag stub before load** (line ~179). Tags load on first interaction, so a
  call-button tap in the gap between interaction and `gtag.js` arriving would
  otherwise be dropped — worst on mobile data, and it eats the single
  highest-intent action on the site.
- **Deferred loading.** Marketing tags are not in the critical path.

## Finding 1 — the quote flow is invisible to GA4

**Severity: high. This is the one worth fixing.**

`/request-a-quote` went live 2026-08-27 and the commercial hiring sheet on
2026-08-28. Commercial CTAs across the site were repointed at that flow in
PRs #190–#193 (2026-08-29). It is now the site-owned capture path.

It fires no analytics event of any kind:

| File | Analytics calls |
| ---- | --------------- |
| `src/components/RequestQuoteForm.astro` | none |
| `src/components/HiringSheetForm.astro` | none |
| `src/pages/request-a-quote.astro` | none |

Production HTML confirms the form posts to `/quote-submit` with no tracking
around the `fetch`.

Consequence: GA4 (and PostHog, and Meta) cannot count a single quote
submission. Leads are arriving — n8n and GHL have them — but no analytics
system can attribute them to a page, a channel, or a campaign. Every
commercial CTA change merged in #190–#193 is currently unmeasurable, so there
is no way to tell whether moving CTAs off BookingKoala helped or hurt.

This also means the conversion-rate question that drives the whole GROW
REVENUE goal cannot be answered for the newest and most important funnel.

## Finding 2 — phone taps reach GA4 with no usable name

`BaseLayout.astro:985` sends a phone tap as:

```js
gtag("event", "click", { event_category: "contact", event_label: "phone", value: href });
```

That is the Universal Analytics category/label idiom. In GA4:

- The event name is `click`, which collides with GA4's own enhanced-measurement
  outbound-click event. Phone taps, email taps and generic outbound clicks all
  pile into one bucket.
- `event_category` / `event_label` are not GA4 dimensions. Until each is
  registered as a custom dimension in the GA4 UI, they are collected but not
  reportable — you cannot segment phone from email.
- A `click` event cannot sensibly be marked as a key event, because that would
  also convert every outbound click.

PostHog gets this right (`phone_click`, line 997, with page path, scroll depth
and seconds-on-page). GA4 is the weaker of the two on the site's primary
conversion.

`BookingCTA.astro:76` has the same shape but at least uses a distinct name
(`cta_click`), so it is reportable by name.

## Finding 3 — likely no key events configured

Follows from findings 1 and 2: the quote flow emits nothing, and phone taps
arrive as `click`. There is probably no event in the property that is both
well-named and marked as a key event, which would mean GA4 shows traffic and
zero conversions.

This is a GA4 dashboard setting, not code — confirmed by the "Key events"
section of `npm run ga4` once access is granted.

## Recommended fixes, in order

1. **Instrument the quote flow.** Fire on successful submit, in all three
   systems, named consistently: GA4 `generate_lead`
   (a GA4 recommended event name, so it gets first-class treatment), PostHog
   `quote_submitted`, Meta `Lead`. Include `form_type` (quote vs hiring sheet)
   and `service` so the `?service=commercial` param is attributable.
2. **Give phone taps a real GA4 event name.** Add `gtag("event",
   "phone_click", …)` alongside the existing `click` call rather than
   replacing it — keeping the old one avoids breaking any historical
   comparison — then mark `phone_click` as a key event in GA4.
3. **Mark key events in the GA4 UI** once 1 and 2 are deployed and confirmed
   arriving.

Fixes 1 and 2 are small, contained edits. Neither adds client JavaScript
beyond a few lines inside handlers that already exist, so the performance
rules in CLAUDE.md hold.

## Not doing

- No change to the production-hostname guard, the gtag stub, or deferred tag
  loading. All three are deliberate and documented in-file.
- No GTM container. The site calls gtag directly; adding a tag manager is a
  bigger architectural change than this problem needs.

## Addendum — first live GA4 read, same day

Read access came online after the above was written. Property **352333734**
(the ID already in Vercel; `35233734` and `533401534` return 403 — real
properties the service account is not on). Findings 1 and 2 confirmed as
written. Finding 3 was understated, and two same-day observations were wrong.

**Finding 3 is worse than predicted.** `page_view` IS marked as a key event —
2,916 of them. GA4 therefore reports a 100% conversion rate on every pageview.
It is not failing to measure conversion; it is reporting a false one. Fix:
GA4 Admin → Events → untoggle "Mark as key event" for `page_view`.

Corroborating finding 1: `form_start` fires 132 times (GA4 enhanced
measurement picks the form up automatically) with **no** `form_submit` and no
lead event. GA4 could see people begin the quote form and never learn whether
any finished.

**Correction — preview pollution is NOT ongoing.** Eight `*.vercel.app`
hostnames appear in a 28-day view, which looked like the PR #167 guard had
failed. Per-day data shows the opposite: preview sessions run 2026-08-03 to
2026-08-22 and stop dead. 1,251 sessions total, spiking 378 on Aug 10 and 324
on Aug 11 (Lighthouse CI). Zero since Aug 22 — the guard shipped and holds.

**Correction — in-market share is 50%, not 17%.** The 28-day view showed
Alabama third behind Virginia and California, at 17% combined AL+TN. That was
the preview traffic carrying datacenter geography. Since 2026-08-23: Alabama
73, Tennessee 38, of 220 sessions — **50% in-market**, with AL and TN as the
top two regions. Normal and healthy for a local service business.

**Consequence: no GA4 baseline may span dates before 2026-08-23.** Anything
earlier is ~6x inflated with false geography, and would make post-fix numbers
look like a collapse.

**Still open — BookingKoala shares this property.**
`thevalleycleanteam.bookingkoala.com` is 44 of 220 clean sessions (20%), and
carries `BookingByCustomer` / `BookingByAdmin` events. Site and booking-system
traffic are blended in one property, which is why `/booknow` appears as a
landing page. Worth separating now that BK is out of customer-facing paths.
